# React Native Architecture Starter

هاد المشروع هو قالب بنستخدمه لننظم مشاريع React Native باستخدام Expo Router وTypeScript.

الفكرة منه بسيطة: بدل ما نحط كل ملفات المشروع بمكان واحد، منقسم المشروع لمجلدات، وكل مجلد إله وظيفة محددة.

هيك بيصير المشروع أسهل بالفهم والتعديل والتطوير، خصوصاً لما يكبر ويصير فيه شاشات وميزات كتيرة.

## 2. شرح المجلدات

### 📁 app

هاد المجلد مسؤول عن التنقل بين شاشات التطبيق (Navigation).

نحن عم نستخدم Expo Router، وهو بيعتمد على الملفات الموجودة داخل `app` لتحديد مسارات الصفحات.

- `index.tsx`: الصفحة الرئيسية للمسار `/`.
- `_layout.tsx`: إعداد التنقل بين الصفحات، مثل Stack أو Tabs، وإعدادات مشتركة للمسارات.

**ليش ما منحط تصميم كل الشاشات هون؟**

لأننا بدنا نفصل بين التنقل وتصميم الشاشة نفسها.

ملفات التنقل بتكون هون، أما تصميم الشاشة ومنطقها فبيكون داخل الـ Feature التابعة إلها.

### 📁 features

هاد أهم مجلد تقريباً بالبنية.

كل Feature معناها ميزة أو قسم من التطبيق.

مثلاً:
- auth: تسجيل الدخول وإنشاء الحساب.
- profile: الملف الشخصي.
- products: المنتجات.

كل ميزة بتحتوي الملفات الخاصة فيها، حتى ما تتداخل مع باقي الميزات.

حالياً عنا:

```text
features/
└── auth/
    ├── components/
    ├── constants/
    ├── interfaces/
    ├── screens/
    └── utils/
```

وظيفة كل مجلد:

- `components`: عناصر واجهة خاصة بميزة تسجيل الدخول، مثل LoginForm.
- `constants`: قيم ثابتة خاصة بالميزة.
- `interfaces`: تعريف شكل البيانات باستخدام TypeScript، مثل بيانات تسجيل الدخول والمستخدم.
- `screens`: الشاشات الخاصة بالميزة، مثل LoginScreen وRegisterScreen.
- `utils`: دوال مساعدة خاصة بالميزة.

**مثال:**

إذا عندنا شاشة تسجيل دخول، تصميمها بيكون داخل `screens`، وإذا فيها نموذج خاص فيها ممكن نحطه داخل `components`.

أما إذا عنا زر عام منستخدمه بكل التطبيق، ما منكرره هون، منحطه داخل `components` الرئيسي.

### 📁 components

هون منحط عناصر الواجهة المشتركة (Shared Components)، يعني العناصر اللي ممكن نستخدمها بأكثر من شاشة أو Feature.

مثلاً:
- CustomButton
- CustomInput
- LoadingIndicator
- CustomModal

القاعدة بسيطة:

إذا العنصر خاص بميزة واحدة، منحطه داخلها.

إذا مشترك بين عدة ميزات، منحطه هون.

### 📁 constants

هون منحط القيم الثابتة اللي منحتاجها بأكثر من مكان بالتطبيق.

مثلاً:
- ألوان التطبيق.
- أحجام الخطوط.
- المسافات.
- قيم وإعدادات ثابتة.

الهدف إننا ما نكرر نفس القيم بكل شاشة، وإذا بدنا نغير لون أو قيمة منقدر نعدلها من مكان واحد.

### 📁 services

هون منحط الخدمات اللي بتتعامل مع أشياء خارج واجهة التطبيق.

مثلاً:
- الاتصال بالـ API.
- إعداد Axios.
- التعامل مع التخزين المحلي.
- إرسال واستقبال البيانات من السيرفر.

إذا العملية خاصة بميزة واحدة، ممكن تكون داخل الـ Feature نفسها.

أما الإعدادات والخدمات المشتركة، فمنحطها هون.

### 📁 assets

هاد المجلد للملفات اللي منستخدمها داخل الواجهات.

قسمناه إلى:

- `fonts`: ملفات الخطوط.
- `icons`: الأيقونات.
- `images`: الصور والرسومات.

### 📁 hooks

هون منحط الـ Custom Hooks اللي منكتبها نحن.

طيب شو هو Hook؟

هو دالة خاصة بـ React بتسمح لنا نستخدم ميزات React، مثل إدارة الحالة ومتابعة التغييرات.

في Hooks جاهزة من React، مثل:

- `useState`: لتخزين قيمة ممكن تتغير.
- `useEffect`: لتنفيذ عملية عند حدوث تغيير معين.
- `useContext`: للوصول إلى بيانات مشتركة.

أما الـ Custom Hooks فهي دوال منكتبها نحن حتى نعيد استخدام منطق معين بأكثر من مكان.

مثلاً:
- `useAuth`: للتعامل مع حالة تسجيل الدخول.
- `useDebounce`: لتأخير تنفيذ البحث.
- `useNetworkStatus`: لمعرفة حالة الاتصال بالإنترنت.

**ملاحظة:** مو كل Hook لازم يكون هون. إذا كان خاص بميزة معينة، ممكن نحطه داخل الـ Feature نفسها.

### 📁 i18n

اختصار لـ Internationalization، يعني تجهيز التطبيق ليدعم أكثر من لغة.

حالياً جهزنا هالبنية:

```text
i18n/
└── locales/
    ├── ar.json
    └── en.json
```

- `ar.json`: النصوص العربية.
- `en.json`: النصوص الإنجليزية.
- `locales`: المجلد اللي بيجمع ملفات اللغات.

الفكرة إننا نخلي نصوص التطبيق بملفات منفصلة بدل ما نكتبها مباشرة داخل الشاشات.

هيك منقدر نغير اللغة بدون ما نعدل كل شاشة لحالها.

لسا ما ركبنا نظام الترجمة نفسه، نحن حالياً جهزنا المجلدات والملفات فقط.

وكمان لازم ننتبه إن العربية اتجاهها من اليمين لليسار (RTL)، والإنجليزية من اليسار لليمين (LTR).

### 📁 providers

هون منحط الـ Providers اللي بتوفر بيانات أو إعدادات مشتركة لأجزاء التطبيق.

مثلاً:
- AuthProvider: لمشاركة حالة تسجيل الدخول.
- ThemeProvider: لمشاركة إعدادات الثيم.
- LanguageProvider: لمشاركة اللغة الحالية.

بدل ما نمرر نفس البيانات بين مكونات كتيرة، منقدر نوفرها من مكان مشترك.

### 📁 types

هون منحط تعريفات أنواع البيانات المشتركة باستخدام TypeScript.

مثلاً:
- نوع بيانات المستخدم.
- نوع استجابة الـ API.
- أنواع بيانات مشتركة بين عدة Features.

### 📁 utils

هون منحط الدوال المساعدة العامة اللي ممكن نستخدمها بأكثر من مكان.

مثلاً:
- تنسيق التاريخ.
- التحقق من البريد الإلكتروني.
- تنسيق الأرقام.
- تحويل النصوص.

الفرق بينها وبين `hooks`:

- `utils`: دوال عادية ما بتحتاج ميزات React.
- `hooks`: دوال بتستخدم ميزات React Hooks.

## 3. كيف منستخدم القالب بمشروع جديد؟

### الطريقة الأساسية

1. إنشاء مشروع Expo جديد:

```bash
npx create-expo-app@latest my-app
```

2. نسخ مجلد `src` الموجود بهالقالب إلى المشروع الجديد.

3. التأكد من وجود ملفات إعدادات Expo Router وTypeScript والتبعيات المطلوبة.

4. تثبيت التبعيات:

```bash
npm install
```

5. تشغيل المشروع:

```bash
npx expo start
```

**ملاحظة:** إذا كان المشروع الجديد مبني مسبقاً على قالب Expo، لازم ننتبه ما نستبدل إعداداته بشكل عشوائي، ونحافظ على بنية `src` الخاصة بالقالب.

## 4. خطوات تأسيس مشروع Tarteel باستخدام القالب

بهالمشروع طبقنا طريقة مختلفة شوي، لأننا كان عنا Repository جاهز فيه البنية المعمارية، وبدنا نضيف عليه إعدادات Expo بدون ما نخسر تقسيم الملفات.

### الخطوة 1: إنشاء Repository وتجهيزه

- إنشاء Repository جديد على GitHub باسم `trtel-app`.
- استنساخ المستودع على الجهاز.
- فتح مجلد المشروع والتأكد من وجود مجلد `.git`.
- إضافة البنية المعمارية الخاصة بالقالب داخل المشروع.

### الخطوة 2: إنشاء مشروع Expo مؤقت

من داخل مجلد المشروع الأساسي نفّذنا:

```bash
npx create-expo-app@latest trtel-temp
```

- اخترنا إصدار Expo المتاح وقت إنشاء المشروع.
- وافقنا على تخطي إنشاء Git Repository جديد للمشروع المؤقت، لأن المشروع الأساسي عنده Repository خاص فيه.

**ليش أنشأنا مشروع مؤقت؟**

حتى ناخد منه ملفات إعدادات Expo والتبعيات والمجلدات المطلوبة، وننقلها لمشروعنا الأساسي بدون استبدال البنية المعمارية.

### الخطوة 3: نقل الملفات المطلوبة

نسخنا الملفات والمجلدات التالية من `trtel-temp` إلى جذر المشروع الأساسي:

```text
assets/
scripts/
app.json
package.json
package-lock.json
tsconfig.json
.gitignore
```

الأوامر المستخدمة في PowerShell:

```powershell
Copy-Item .\trtel-temp\assets .\assets -Recurse
Copy-Item .\trtel-temp\scripts .\scripts -Recurse

Copy-Item .\trtel-temp\app.json, .\trtel-temp\package.json, .\trtel-temp\package-lock.json, .\trtel-temp\tsconfig.json, .\trtel-temp\.gitignore -Destination .
```

**مهم:** ما نسخنا مجلد `src` من المشروع المؤقت، حتى نحافظ على البنية المعمارية الأصلية.

### الخطوة 4: تعديل إعدادات المشروع

عدّلنا اسم المشروع في `package.json`:

```bash
npm pkg set name="trtel-app"
```

وعدّلنا القيم التالية في `app.json`:

```json
{
  "expo": {
    "name": "Tarteel",
    "slug": "trtel-app",
    "scheme": "tarteel"
  }
}
```

وتأكدنا من وجود إعداد Expo Router في `package.json`:

```json
"main": "expo-router/entry"
```

وكمان راجعنا إعدادات TypeScript في `tsconfig.json`.

### الخطوة 5: تثبيت التبعيات

من داخل مجلد المشروع الأساسي نفّذنا:

```bash
npm install
```

هاد الأمر ثبّت المكتبات المطلوبة للمشروع وأنشأ مجلد `node_modules` الخاص فيه.

### الخطوة 6: إعداد Expo Router

تأكدنا من وجود:

```text
src/
└── app/
    ├── index.tsx
    └── _layout.tsx
```

وعدّلنا ملف `_layout.tsx` حتى يستخدم Stack من Expo Router:

```tsx
import { Stack } from "expo-router";
import { StatusBar } from "expo-status-bar";

export default function RootLayout() {
  return (
    <>
      <StatusBar style="auto" />
      <Stack
        screenOptions={{
          headerShown: false,
        }}
      />
    </>
  );
}
```

- `Stack`: مسؤول عن التنقل بين الشاشات.
- `headerShown: false`: لإخفاء الهيدر الافتراضي.
- `StatusBar`: للتحكم بشريط حالة الجهاز.

### الخطوة 7: فحص المشروع وتشغيله

فحصنا إعدادات Expo باستخدام:

```bash
npx expo-doctor
```

النتيجة:

```text
20/20 checks passed.
No issues detected!
```

وبعدها شغّلنا المشروع:

```bash
npx expo start
```

وتأكدنا من نجاح تشغيل Metro Bundler، وظهور QR Code ورابط الويب:

```text
http://localhost:8081
```

كما تأكدنا أن Expo Router يستخدم `src/app` كمجلد أساسي للمسارات.

### الخطوة 8: تنظيف المشروع المؤقت

بعد التأكد من تشغيل المشروع الأساسي، حاولنا حذف مجلد `trtel-temp`:

```powershell
Remove-Item .\trtel-temp -Recurse -Force
```

واجهنا مشكلة أثناء حذف بعض الملفات الطويلة داخل `node_modules`، لذلك لم يكتمل الحذف بهذه المحاولة.

جرّبنا طريقة بديلة:

```powershell
cmd /c "rmdir /s /q trtel-temp"
```

ثم نتحقق من وجود المجلد:

```powershell
Test-Path .\trtel-temp
```

النتيجة المطلوبة:

```text
False
```

بعد التأكد من الحذف، بيكون المشروع الأساسي هو النسخة الوحيدة اللي منشتغل عليها.

## 5. كيف أرفع تعديلاتي على GitHub؟

كل ما أعمل أي تعديل على المشروع وبدي أرفعه على GitHub، بفتح Terminal داخل مجلد المشروع وبنفّذ الخطوات التالية بالترتيب:

### 1. التأكد من التعديلات

```bash
git status
```

بيعرضلي الملفات اللي تعدّلت أو انضافت أو انحذفت.

### 2. تجهيز التعديلات للرفع

```bash
git add .
```

بيجهّز كل التعديلات والملفات الجديدة للـ Commit.

### 3. حفظ التعديلات

```bash
git commit -m "وصف مختصر للتعديل"
```

بيحفظ التعديلات ضمن نسخة جديدة، ولازم أغيّر الوصف حسب طبيعة التعديل.

### 4. رفع التعديلات على GitHub

```bash
git push
```

بيرفع آخر Commit على المستودع الموجود على GitHub.

### الأوامر السريعة

```bash
git add .
git commit -m "Describe your changes"
git push
```

## 6. Development Workflow

بعد الانتهاء من تأسيس المشروع، بيكون ترتيب التطوير كالتالي:

1. إعداد Design System: الألوان، الخطوط، المسافات، أحجام النصوص والثوابت.
2. إعداد الخطوط والأصول البصرية.
3. تجهيز المكونات المشتركة.
4. إعداد التنقل بين الشاشات.
5. تطوير الميزات والشاشات حسب تقسيم `features`.
6. ربط الخدمات وواجهات API.
7. الاختبار ومعالجة الأخطاء.
8. توثيق التغييرات ورفعها إلى GitHub بشكل مستمر.
